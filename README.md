# srez

![srez](./docs/images/srez.png)

Локальное приложение для анализа вакансий hh.ru. Собирает вакансии по поисковому запросу, показывает зарплаты, навыки, требования и отклики. Работает без LLM и платных API. Предоставляет подробные отчеты по множеству параметров, со ссылками на исходные вакансии. 

__‼️ Приложение использует локальные сессии для парсинга вакансий, для работы необходим аккаунт hh.ru. 
Сессии, пароли и прочие пользовательские данные хранятся локально и не покидают ваше устройство__

## Возможности
- Поиск по ключевым словам, автоматическая оптимизация запросов для расширения релевантной выборки, поддержка языка поисковых запросов hh.ru.
- Фоновый сбор информации с остановкой и продолжением, сохранение истории и снимков вакансий.
- Каждый анализ сохраняет все найденные ссылки, включая вакансии из других анализов. Ссылки из HTML и начального состояния страницы объединяются по ID вакансии.
- Распределения по регионам, опыту, грейдам и форматам работы; зарплаты в рублях в месяц на руки.
- Навыки, обязательные требования и пожелания с частотой упоминаний и цитатами из вакансий.
- Фильтрация всего отчёта по категориям, просмотр вакансий и источников метрик.

## Установка и запуск

Требования: Docker, Node.js 22.13 или новее и браузер на базе Chromium для входа в hh.ru.

1. Установите [api-anything](https://github.com/goodnight000/api-anything) на компьютере:

   ```sh
   npm install -g api-anything
   ```

2. Войдите в hh.ru через api-anything, если ещё не авторизованы:

   ```sh
   api-anything login hh --window
   ```

   Завершите вход в открывшемся окне и закройте его. Файл сессии должен находиться в `~/.api-anything/sessions/hh.json`.

3. Из корня проекта запустите контейнеры:

   ```sh
   docker compose up --build -d
   ```

4. Откройте [localhost:3000](http://localhost:3000).

Приложение доступно только с локального компьютера. API и PostgreSQL не публикуют порты наружу.

### Настройки

При необходимости скопируйте `.env.example` в `.env`:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `APP_PORT` | Порт приложения | `3000` |
| `API_ANYTHING_SOURCE` | Каталог api-anything с файлом `sessions/hh.json` | `~/.api-anything` |
| `POSTGRES_PASSWORD` | Пароль локальной базы | `hh-local-development` |

### Управление

```sh
docker compose logs -f api runner  # журналы сбора
docker compose down                # остановка с сохранением данных
```

История хранится в Docker volume `hh-analytics_postgres_data`, данные runner в `hh-analytics_runner_data`. Команда `docker compose down -v` удаляет эти данные.

Если сессия hh.ru истекла, повторите `api-anything login hh --window` и нажмите «Продолжить сбор» в приложении. Пересборка не нужна. Если файл сессии был заменён целиком, пересоздайте runner:

```sh
docker compose up -d --force-recreate runner
```

## Особенности данных

- Сбор идёт через api-anything последовательно, с паузами. Для временных ошибок, неполных описаний, пустых и повторных страниц предусмотрено до трёх попыток с увеличением задержки. Учитывается `Retry-After`; если источник требует ждать больше минуты, задача сохраняет прогресс и останавливается. При блокировке или необходимости входа сбор тоже останавливается; вход выполняется вручную на компьютере.
- Число уникальных ссылок сверяется с размером страницы и общим числом результатов. При недостаче выполняются ещё два прохода выдачи. Неустранимая ошибка одной вакансии сохраняется и не мешает загрузке остальных; продолжение сбора повторяет незагруженные вакансии. Вакансия считается загруженной только при наличии названия и описания.
- Доступны страницы выдачи с индексами от 0 до 39. Отчёт показывает охват: число найденных вакансий может отличаться от числа загруженных. Сохранённый анализ содержит снимки и не обновляется при открытии.
- Навыки и требования извлекаются по словарям и правилам. Нестандартные формулировки могут не распознаться. Грейд учитывается только при явном указании в вакансии.
- Зарплаты пересчитываются по курсам Банка России с учётом периода выплаты и НДФЛ для резидента РФ. Допущения и дата курса доступны в отчёте. Предложения с недостаточными данными исключаются из графика.
- Графики зарплат и откликов разделены на непрерывные группы грейдов: значения возрастают внутри каждой группы. Цвет грейда одинаков в обоих графиках и сохраняется после фильтрации; каждая группа отмечена общей подписью и линией.
- Офис, удалённая работа и гибрид могут пересекаться, поэтому сумма их долей может превышать 100%. Пропущенные значения откликов исключаются из среднего, реальные нули учитываются.
- Индекс рынка равен среднему числу откликов, делённому на число загруженных вакансий текущей отфильтрованной выборки. Среднее считается по известным значениям, включая нули, без промежуточного округления. Оба показателя пересчитываются после фильтрации; дополнительного ограничения по дате публикации нет.

## Разработка

| Каталог | Содержимое |
| --- | --- |
| `frontend/` | React 19, TypeScript, Tailwind CSS 4, Recharts |
| `api/` | Go API, фоновые задачи, правила аналитики, работа с PostgreSQL 17 |
| `runner/` | Node.js runtime api-anything и операции hh.ru |

Для проверки интерфейса без Docker и БД запустите `(cd frontend && npm run dev:mock)`
и откройте [localhost:5173](http://localhost:5173). Изменения применяются через HMR.
Режим использует вымышленные тестовые данные и хранит изменения в памяти Vite.
Сценарии и сброс данных описаны в [frontend/mocks/README.md](frontend/mocks/README.md).

Для локальных проверок нужны Go 1.26 и Node.js 24. Команды выполняются из корня проекта:

```sh
(cd api && go test ./...)
(cd runner && npm ci && npm test)
(cd frontend && npm ci && npm run build && npm test)
```

Интеграционные тесты PostgreSQL работают в отдельной временной схеме:

```sh
docker compose --profile test run --rm --build api-tests
```
