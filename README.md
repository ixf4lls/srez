# Срез — анализ рынка вакансий hh.ru

Локальное SPA: React 19, TypeScript, Tailwind CSS 4, Go, PostgreSQL 17. Интерфейс следует [Figma UI kit](https://www.figma.com/design/qEnvppqqUuqQSFLRnLke3I): Gotham, светлая основа, фиолетовый и мятный акценты, иконки Iconsax Broken. Шрифтовые файлы предоставлены владельцем проекта. LLM и платные API не нужны.

## Запуск

Из корня проекта, при запущенном Docker Desktop:

```sh
docker compose up --build -d
```

Открыть **http://localhost:3000**. Порт опубликован только на loopback-интерфейсе. Внутренние сервисы и PostgreSQL наружу не публикуются.

Приложение использует существующую авторизацию api-anything: `~/.api-anything/sessions/hh.json`. В текущем окружении она уже настроена. Для нового компьютера один раз установить api-anything и выполнить:

```sh
api-anything login hh --window
```

В открывшемся окне завершить вход и закрыть окно. Пароли и cookies не вводятся в приложение и не хранятся в исходниках. Если сессия истекла, выполнить ту же команду и нажать «Продолжить сбор». Новый файл сессии подхватывается без пересборки. Если нужно пересоздать файл целиком (сменился inode), выполнить `docker compose up -d --force-recreate runner`.

Для другой папки api-anything или порта скопировать `.env.example` в `.env` и изменить `API_ANYTHING_SOURCE` / `APP_PORT`. Настройки необязательны для стандартного запуска.

```sh
docker compose logs -f api runner  # журналы
docker compose down              # остановка с сохранением данных
```

Данные живут в Docker volumes `hh-analytics_postgres_data` и `hh-analytics_runner_data`. Команда `down` не удаляет историю. Не используйте `down -v`, если хотите её сохранить.

## Возможности

- Два режима релевантности: основная технология в названии должности либо поиск стека по всем полям.
- Оптимизация запросов по словарю вариантов названий технологий с использованием языка hh.ru. Несколько технологий соединяются через AND, варианты одного названия — через OR. Готовые выражения с AND/OR/NOT и полями сохраняются как введены.
- Редактирование выражения и явное подтверждение перед сбором. Сервер отклоняет создание анализа без `confirmed: true`.
- Необязательные фильтры. Доступные регионы, опыт, форматы, занятость, образование, специализации, графики и часы читаются с hh.ru через api-anything. Список регионов — доступные варианты текущего поискового кластера, не полный мировой справочник. Фильтры кешируются на шесть часов.
- Фоновый сбор с реальными счётчиками, дедупликацией ID, остановкой и продолжением. Перезагрузка страницы не прерывает работу. После перезапуска API незавершённый анализ можно продолжить из истории.
- Круговые диаграммы географии, опыта и явно указанного грейда. Форматы работы — три пересекающиеся группы: офис, удалённо, гибрид; доля каждого формата считается от числа вакансий, поэтому сумма может превышать 100%.
- Линейный график откликов: точки всех вакансий с доступными значениями соединены линией, показано среднее. Настоящие нули учитываются, пропуски исключаются.
- Колоночный график зарплат по вакансиям с диапазонами. Валюты, периоды оплаты и суммы до/после налогов показываются отдельными группами, без вымышленных конверсий.
- Нажатие на сегмент диаграммы или категорию фильтрует весь отчёт: все графики, навыки, требования, зарплаты, отклики и их источники пересчитываются по текущей выборке. Внутри одного критерия используется ИЛИ, между критериями — И. Активные фильтры и число вакансий закреплены под навигацией.
- Навыки и требования: количество вакансий, процент от всех загруженных вакансий, подтверждающие фрагменты. Синонимы известных технологий нормализуются; повтор навыка в одной вакансии учитывается один раз.
- Источники каждой метрики, просмотр вакансий внутри SPA, подсветка использованных полей и цитат. Оригинальная ссылка доступна отдельно.
- Одиночное и массовое удаление из истории с действием «Отменить». Активные задачи при удалении останавливаются; скрытые записи не воскрешаются запоздавшей записью фонового задания.
- История с неизменяемыми снимками вакансий. Открытие сохранённого анализа не перезапрашивает вакансии на hh.ru. Повторный поиск создаёт новый анализ.

## Получение данных

`runner/operations/hh.json` — экспорт существующих read-only операций api-anything, без cookies и секретов:

- `searchVacancies` — метаданные поисковой страницы;
- `listVacancyLinks` — ссылки и поля карточек;
- `getVacancy` — полное описание и ключевые навыки;
- `getVacancyResponseCount` — шаблон извлечения числа откликов из HTML;
- `getVacancyViewCount` — исходная операция сохранена, просмотры не подменяют отклики.

Служебный Node-контейнер нужен для runtime api-anything. Вся логика задач, запросов, аналитики и хранения реализована на Go. Runner повторно использует известные запросы и CSS-рецепты. Из ответа той же страницы дополнительно читает публичные поисковые кластеры и все карточки из HH InitialState: HTML может содержать только первые 20 из 50 результатов страницы. Пагинация учитывает `paging.next` и `totalResults`. Для описаний сохраняются границы абзацев; для откликов применяется существующий regex из `getVacancyResponseCount` к уже полученной странице, без второго сетевого запроса.

Невыбранные фильтры удаляются из URL и схемы операции в изолированной runtime-копии. Исходные операции на компьютере не меняются. В runtime копируется только сессия hh.ru; каталог других сессий не монтируется. Обращения к hh.ru идут последовательно с паузой api-anything. При авторизации, блокировке, rate limit или изменении страницы задача сохраняет прогресс и останавливается. Автоматического обхода ограничений и бесконечных повторов нет.

Известные операции ограничены страницами 0–39. При достижении лимита или неполном сборе отчёт явно показывает охват. Число найденных вакансий и число успешно загруженных различаются. Содержимое выдачи hh.ru может меняться во время длительного сбора, поэтому снимок фиксирует время загрузки каждой вакансии.

Runtime работает через HTTP (tier 1), используя импортированную сессию. Браузер и повторный вход выполняются на компьютере через api-anything. В контейнер не включён браузерный fallback: при challenge нужен ручной вход.

## Анализ без LLM

Правила находятся в `api/internal/core`:

- словарь технологий с границами слов: Go не совпадает с Django/Google, Java с JavaScript, C++ с C#;
- явные секции требований и пожеланий, распознавание отрицаний;
- словари технологий, архитектуры, тестирования, командной работы и других требований;
- неизвестные короткие требования сохраняются дословно с исходной цитатой;
- обязательные требования и «будет плюсом» считаются отдельно;
- опыт не используется для угадывания грейда.

Это детерминированное извлечение, а не семантическая модель. Необычная структура описания, сложные отрицания и нестандартные названия могут не распознаться. Каждый вывод содержит источник; покрытие показано в отчёте. Словари можно расширять без изменения инфраструктуры.

## Проверки

```sh
cd api
go test ./...

cd ../runner
npm ci
npm test

cd ../frontend
npm ci
npm run build
npm test
```

Интеграционный тест PostgreSQL выполняется в отдельной временной схеме и не меняет сохранённые анализы:

```sh
docker compose --profile test run --rm --build api-tests
```

Тесты проверяют границы технологий, сохранение явно заданной поисковой логики, обязательное подтверждение, секции требований, отрицания, цитаты, расчёт процентов, пропущенные и нулевые отклики, сочетания форматов, чтение фильтров из HH InitialState и сбор всех 50 результатов при неполном HTML.

При проверке приложения выполнены реальные анализы Rust, включая выборку из 24 вакансий: подтверждение изменённого запроса, фильтры, остановка и продолжение, дозагрузка неполной выборки, история после перезапуска контейнеров, источники диаграмм и подсветка цитат. Тестовые отчёты оставлены в локальной истории для просмотра.

## Структура

```text
frontend/   React SPA, Tailwind, Recharts, доступные диалоги Radix
api/        Go HTTP API, фоновая очередь, PostgreSQL, правила аналитики
runner/     runtime api-anything и известные операции hh.ru
compose.yaml
```

Основные маршруты API: `GET /api/health`, `GET /api/filters`, `POST /api/prepare`, `GET|POST /api/analyses`, `GET /api/analyses/{id}`, `GET /api/analyses/{id}/vacancies`, `POST /api/analyses/{id}/cancel`, `POST /api/analyses/{id}/resume`, `POST /api/analyses/delete`, `POST /api/analyses/restore`.
